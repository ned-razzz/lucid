네. **공통 원칙이 중심이고 작업에 따라 적용 방식만 달라진다면, 하나의 lucid에 references를 나누는 편이 더 단순하고 적절합니다.** 앞서 저는 작업별 차이를 크게 보고 분리를 권했는데, 그 차이를 반드시 별도 스킬로 관리할 필요는 없습니다.

두 작업 모두 “첫 독해에서 이해하게 한다”, “의미 연결을 보존한다”, “불필요한 내용을 제거한다”는 원칙을 공유합니다. 이를 두 스킬에 복제하면 수정할 때 서로 달라질 수 있습니다.

다음처럼 구성하면 됩니다.

| 파일 | 담당하는 내용 |
|---|---|
| `SKILL.md` | 공통 명료성 원칙과 작업별 참고 지침 선택 기준 |
| `references/explanation.md` | 질문에 직접 답하기, 대화 맥락 활용, 필요한 배경과 원리 설명 |
| `references/document.md` | 제3자를 위한 맥락 제공, 문서 목적과 범위 준수, 기존 형식 보존, 메타 정보 제거 |
| `references/ko.md`, `en.md` | 언어별 표현 지침 |

핵심은 **SKILL.md에서 어떤 reference를 읽을지 명확하게 정하는 것**입니다.

- 질문에 답하거나 개념·원인을 설명할 때는 `explanation.md`를 적용합니다.
- 문서를 작성·수정할 때는 `document.md`를 적용합니다.
- 문서를 수정하면서 변경 이유도 설명한다면, 문서에는 문서 지침을, 답변에는 설명 지침을 적용합니다.

다만 짧은 지침까지 모두 참고 파일로 옮길 필요는 없습니다. 처음에는 공통 원칙과 작업별 차이를 SKILL.md에 간단히 두고, 세부 지침이 길어질 때 references로 분리해도 됩니다.
