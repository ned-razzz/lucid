| **이름과 표현에서 역할을 드러내기** | 제목·클래스명·화살표 메시지만 봐도 기능이나 책임이 떠오르게 쓴다. 모호한 이름, 긴 메시지, 중복 표현을 다듬는다. |
| **문서의 목적과 현재 범위에 맞추기** | 요구사항은 무엇을 만들지, 설계는 구조와 동작을 설명한다. 현재 단계에서 필요하지 않은 상세 설계나 과도한 절차·추적 정보를 추가하지 않는다. |
