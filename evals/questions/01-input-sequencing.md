# 사람 입력 패턴 모델과 키보드 실행 경로의 설계 검토

`bubembe/src/bubembe/keyboard.py`의 키보드 입력을 사람의 입력 패턴에 가깝게
만들려고 한다. 현재 정책이 요청한 키 조합에 시간 간격을 조금 추가하는 수준을
넘어, 방향키 전환과 점프·로프 진입에서 실제 키 전환 순서를 재현해야 한다.
학습 모델만 추가하면 되는지, 실행 경로까지 어떻게 바꿔야 하는지 설계를 검토해 줘.

관련 코드 조사와 수집 자료에서 확인한 내용은 다음과 같다.

- `HumanInputModel.adjust()`는 정책이 요청한 키 조합을 받아 키 이름들의 튜플을
  반환한다. 예를 들어 `("VK_LMENU", "VK_RIGHT")`를
  `("VK_RIGHT", "VK_LMENU")`로 재정렬할 수 있다.
- 현재 `InputExecutor.sync()`는 원하는 키 상태를 한 번에 전송한다. HID 보고서는
  그 시점에 눌려 있는 키들의 상태를 표현한다. `KeyboardController.execute()`가
  모델의 반환값을 받아 이 경로로 입력을 보낸다.
- 상위 제어 판단은 15Hz로 실행된다. 새 정책 판단, 중지 요청, 포커스 이탈이
  기존 입력 시퀀스 재생과 겹칠 수 있다. 최종 키 상태는 최신 정책 요청과 같아야
  하며 중지·포커스 이탈 시에는 누른 키를 해제해야 한다.
- 기존 `human_input_model_statistic`은 주어진 키 누름·뗌 순서를 유지하면서
  시간 간격을 생성한다. 순서 자체를 고르는 모델은 아니다.
- 그 통계 모델에 사용한 기록은 한 세션의 전환 88개이고 첫 이벤트가 `RIGHT/up`이다.
  별도로 수집한 두 사람 입력 기록의 유효 전환은 총 129개이며 `UP` 전환은 7개다.
- 현재 `training/human_input/fit.py`는 같은 종류의 전환이 30ms 이내에 이어진
  경우를 묶어 키 순서와 시간 간격을 저장한다. 여기서 종류는 누름 또는 뗌이다.
  누름과 뗌이 섞인 장기 시퀀스는 이 방식의 학습 대상이 아니다. 현재 저장된
  묶음 모델에는 두 키를 떼는 샘플이 1개만 있다.

이 상태에서 `adjust()`의 튜플 순서만 바꾸는 접근이 실제 입력 순서에 어떤 영향을
주는지 판단하고, 모델이 결정할 내용과 실행기가 책임질 내용을 나눠 제안해 줘.
특히 방향키를 누른 뒤 점프를 누르는 경우와 반대 방향으로 전환하는 경우에,
게임으로 전달되는 키 상태가 시간에 따라 어떻게 달라지는지 보여 줬으면 한다.

현재 자료 규모에서 채택할 패턴 모델, 입력 시퀀스를 재생하는 방식, 제어 주기와
취소·키 해제 처리를 함께 고려해 비용 대비 효과가 좋은 최소 변경안을 제시해 줘.
사람다운 패턴을 만들었다는 주장과 실제 제어가 올바르다는 주장을 각각 어떤
기록 재생 검사와 실환경 비교로 확인할지도 설명해 줘. 지금은 파일을 수정하지 말고
구현 전 설계 판단을 내려 줘.
