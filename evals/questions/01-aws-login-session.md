# AWS 서버를 두 대로 늘린 뒤 로그인이 자꾸 풀리는 이유는 뭘까?

작은 쇼핑몰을 AWS에서 운영하고 있다. 접속자가 늘어 웹 서버를 한 대에서 두 대로
늘렸더니, 로그인 직후에도 페이지를 새로 고치면 가끔 로그인이 풀린다. 한 대로
운영할 때는 없던 문제다.

현재 구성은 다음과 같다.

- 웹 서버는 AWS의 가상 서버인 EC2 두 대에서 같은 프로그램을 실행한다.
- 앞에는 요청을 두 서버에 나눠 보내는 로드 밸런서(ALB)가 있다.
- 로그인에 성공하면 서버는 자기 메모리에 로그인 정보를 저장하고, 브라우저에는
  그 정보를 찾을 수 있는 번호를 쿠키로 보낸다. 이후 요청에서는 쿠키의 번호로
  로그인 여부를 확인한다.
- 로그를 보니 같은 브라우저의 요청이 두 서버를 번갈아 방문한다. 로그인한
  서버에서는 번호를 찾지만, 다른 서버에서는 같은 번호를 찾지 못한다.
- 서버를 재시작해도 그 서버에 로그인했던 사용자의 로그인이 풀린다.

동료는 ALB에서 같은 사용자의 요청을 계속 같은 서버로 보내도록 설정하면
해결된다고 한다. 이 설정만으로 충분할까? 배포하거나 서버 한 대가 고장 나도
사용자가 다시 로그인하지 않게 하려면 로그인 정보 저장 방식을 어떻게 바꿔야 할까?

당장 증상을 줄이는 방법과 배포·장애 때도 로그인을 유지하는 해결책을 비교하고,
이 쇼핑몰에 적용할 방식을 제안해 줘. 로그인부터 다음 페이지 요청까지 정보가
어디에 저장되고 어떻게 확인되는지, 로그아웃과 로그인 만료는 어떻게 처리되는지도
포함해 줘. 변경 후에는 어떤 순서로 시험해야 문제가 해결됐다고 판단할 수 있을까?

전체 AWS 구성을 새로 설계할 필요는 없고, 이 로그인 유지 문제에 집중해 줘.
