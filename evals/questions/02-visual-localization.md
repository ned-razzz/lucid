# 영상 기반 맵 생성과 런타임 위치 추정의 좌표계 설계 검토

`bubembe`에서 플레이 영상을 이용해 발판·로프 맵을 만들고, 실행 중 현재 화면이
맵의 어디에 있는지 추정한다. 전체 화면을 이어 붙여 큰 이미지 한 장을 만드는
방식으로 이해했는데, 실제 구현 설명을 보면 키프레임과 optical flow를 사용한다.
여기에 미니맵을 이용한 위치 보정을 넣으려 한다. 맵 생성과 런타임 위치 추정이
같은 좌표 기준을 사용하도록 설계를 검토해 줘.

현재 구현을 조사한 내용은 다음과 같다.

- `map_builder.py`는 영상의 첫 화면을 기준으로 카메라의 맵상 상대 위치를 `(0, 0)`으로
  정한다. 연속 화면의 배경 이동량을 optical flow로 구해 카메라 이동량을 누적한다.
- 마지막 키프레임 위치에서 카메라가 120픽셀 이상 이동하면 화면 일부인 ROI 이미지와
  당시 누적 위치를 저장한다. 특징점 자체를 파일에 저장하는 것은 아니다.
- 맵을 불러올 때 저장된 키프레임 이미지에서 ORB 특징점을 추출한다.
  `MapLocalizer`는 현재 화면과 키프레임의 대응점을 비교해 상대 이동량을 구하고,
  키프레임에 기록된 위치와 결합한다. 이후 프레임은 optical flow로 추적한다.
- terrain 모델의 발판·로프 검출 결과는 각 프레임의 화면 좌표다. 이를 맵상의
  지형으로 합치려면 해당 프레임의 카메라 위치가 필요하다.
- 현재 맵 좌표는 영상에서 만든 상대 좌표이며 외부에서 측정한 절대 위치가 아니다.

추가하려는 미니맵 보정에는 다음 조건이 있다.

- 미니맵의 플레이어 표시 좌표와 본 화면의 플레이어 좌표를 같은 프레임에서
  얻을 수 있다. 본 화면의 플레이어 위치는 이름표 인식 결과를 이용한다.
- 미니맵 좌표를 맵 좌표로 바꾸는 가로·세로 배율과 원점은 처음에 알 수 없다.
  여러 위치에서 얻은 관측을 이용해 추정해야 한다.
- 미니맵 표시는 작은 이미지에서 검출되므로 좌표가 흔들릴 수 있다. 본 화면의
  이름표는 다른 물체에 가려질 수 있고, 미니맵 표시도 검출에 실패할 수 있다.
- optical flow의 누적 오차가 있을 수 있으며 추적 자체가 실패할 수도 있다.
  저장된 키프레임은 위치를 다시 찾는 데 사용할 수 있다.
- 맵 생성 시 카메라 경로를 보정한 뒤 발판·로프의 맵 좌표를 확정하는 안을
  검토 중이다. 미니맵 보정이 안정적으로 작동한다는 실측 결과는 아직 없다.

영상에서 맵을 만드는 과정과 실행 중 위치를 찾는 과정을 연결해서 설명해 줘.
플레이어의 화면 좌표, 카메라 위치, 플레이어의 맵 좌표, 미니맵 좌표가 각각
무엇을 나타내며 어떤 관계로 변환되는지 수치 예시를 포함해 보여 줬으면 한다.

그 관계를 바탕으로 미니맵의 배율·원점 추정과 optical flow의 경로 보정을 어떻게
분리해야 하는지, 현재 관측만으로 어떤 기준을 정할 수 있고 무엇은 확정할 수
없는지 검토해 줘. 한 방향으로만 이동한 영상에서도 두 축을 충분히 보정할 수
있는지와, 위치를 다시 찾았을 때 기존 지형 기록을 어떻게 다룰지도 판단해 줘.

마지막으로 인식과 추적이 각각 실패하는 경우의 진행·보류·복구 조건을 제안하고,
그 판단을 다음 실행에서도 재현하려면 맵 파일에 어떤 정보를 함께 보관해야
하는지 설명해 줘. 구현된 동작과 제안하는 변경은 구분하고, 코드는 수정하지 마.
