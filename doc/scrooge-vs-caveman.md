## 결론

이 저장소의 목표에는 **Scrooge가 더 적합하다**. Scrooge는 한국어와 영어만 지원한다는 범위에 맞춰 언어별 규칙을 분리했고, 한국어 압축 품질과 입력 비용에서 우세하다. Caveman은 영어 규칙, 안전 장치, 외부 산출물 경계가 더 세밀하지만 이 저장소에 필요하지 않은 강도 및 중국어 문어체 모드까지 포함한다.

아래 점수는 파일 구조와 지침을 분석한 정적 평가다. 동일한 모델과 질문 세트를 사용한 출력 품질 및 실제 토큰 비교 실험은 포함하지 않았다.

## 1. 성능

### Scrooge의 강점

- 한국어와 영어에 각각 전용 register를 제공한다.
- 한국어 조사 생략 조건과 의미가 뒤집힐 수 있는 경우의 보존 규칙이 있다.
- 한국어 본문에 한자가 섞이는 문제를 명시적으로 방지한다.
- `ko`, `en`, `off` 전환과 언어 override 해제가 명확하다.
- 정식 문서 작성 시 압축을 해제하는 예외가 있다.
- 현재 언어의 reference만 읽으므로 관련 규칙에 집중하기 쉽다.

### Caveman의 강점

- 영어 문법과 명확성 규칙이 더 촘촘하다.
- 부정어, 숫자, 단위를 보존하도록 명시한다.
- 토큰을 줄이지 못하는 인위적 약어와 인과 화살표를 금지한다.
- `lite`, `full`, `ultra`로 압축 강도를 선택할 수 있다.
- 영어만 사용하거나 최대 압축이 목적이면 `ultra`가 더 강하다.

### 판단

Caveman의 한국어 처리는 사용자의 주 언어를 유지하고 조사를 보존하는 수준이다. Scrooge처럼 한국어 출력 형태를 직접 설계하지 않았으므로 한국어 품질과 일관성은 Scrooge가 더 좋을 가능성이 높다.

영어에서는 Caveman이 더 정교하다. 특히 부정어와 수치 보존, 불필요한 약어 금지, 단문 작성 규칙은 정확도 저하를 막는 데 유리하다. 반면 Scrooge의 `req/res` 및 `→` 권장은 가독성 대비 토큰 이득이 불확실하다.

종합하면 한국어와 영어를 함께 사용하는 이 저장소에서는 Scrooge가 우세하다. 영어 전용 환경과 최대 출력 압축만 평가하면 Caveman이 우세할 수 있다.

## 2. 입력 토큰 비용

정확한 토큰 수는 사용하는 모델과 tokenizer에 따라 달라진다. 다음 수치는 실제로 활성화될 파일의 문자 수, 공백 기준 단어 수, UTF-8 byte 수를 입력량 대용치로 측정한 결과다.

| 활성 구성 | 문자 | 공백 기준 단어 | UTF-8 bytes |
|---|---:|---:|---:|
| Scrooge 본문 + KO reference | 5,682 | 925 | 6,874 |
| Scrooge 본문 + EN reference | 5,625 | 857 | 5,641 |
| Caveman 전체 | 6,832 | 980 | 7,022 |

문자 수 기준으로 Scrooge는 Caveman보다 다음과 같이 작다.

- 한국어 활성화: 약 16.8% 감소
- 영어 활성화: 약 17.7% 감소

Scrooge는 공통 규칙과 언어별 규칙을 분리해 현재 필요한 reference만 읽는다. Caveman은 여섯 가지 강도와 중국어 문어체 예시까지 한 파일에 포함하므로 한국어 또는 영어만 사용할 때도 모든 지침이 입력에 들어간다.

한국어는 UTF-8에서 한 글자가 여러 byte를 사용하므로 byte 차이가 작다고 토큰 차이도 작다고 단정할 수 없다. 정확한 비용 비교에는 같은 Codex 모델과 tokenizer를 이용한 실측이 필요하다.

## 3. 스킬 완성도

### Caveman이 더 완성된 부분

- 보안 경고, 파괴적 작업, 모호한 다단계 절차의 압축 해제 조건이 상세하다.
- `not`, `never`, `no`, `only`, `except`와 숫자 및 단위 보존을 명시한다.
- 코드뿐 아니라 문서, issue, PR, 리뷰, 외부 메시지에도 정상 문체를 적용한다.
- 반복 질문을 명확성 부족 신호로 처리한다.
- 압축 강도별 동작 차이와 예시가 있다.

### Scrooge가 더 완성된 부분

- 활성화 명령 해석과 언어 선택 우선순위가 단순하고 결정적이다.
- `off`가 압축과 언어 override를 함께 해제한다고 명시한다.
- 언어별 reference를 지연 로드해 구조가 명확하다.
- 저장소 범위인 한국어와 영어만 지원한다.
- 기능 수보다 목표 적합성과 규칙 밀도가 높다.

### Scrooge의 주요 빈틈

- issue, PR, 리뷰, 외부 메시지 등 사람이 읽는 산출물의 경계가 충분히 명시되지 않았다.
- 부정어, 숫자, 단위 보존 규칙이 없다.
- 실제 압축률과 정확도 회귀를 검증하는 평가 세트가 없다.

OpenAI의 모델 지침은 길고 충돌하는 스킬 지침이 모델 동작을 방해할 수 있다고 설명한다. 따라서 Caveman의 넓은 기능 수가 항상 더 높은 실행 품질을 의미하지는 않는다. 이 저장소처럼 지원 범위가 명확한 경우에는 Scrooge의 좁고 분리된 구성이 더 적합하다.

## 최종 권고

Scrooge를 기본 설계로 유지한다. Caveman 전체를 합치지 말고 다음 두 항목만 Scrooge에 반영하는 것이 가장 효율적이다.

1. 부정어, 숫자, 단위는 압축하지 않는다는 규칙
2. issue, PR, 리뷰, 외부 메시지는 정상 문체로 작성한다는 경계

실제 성능을 확정하려면 한국어와 영어 질문 세트를 각각 준비해 다음 항목을 같은 Codex 모델에서 비교해야 한다.

- 입력 토큰 수
- 출력 토큰 수
- 기술 정보 보존율
- 의미 왜곡 및 모호성 발생률
- 사용자 가독성 평가
